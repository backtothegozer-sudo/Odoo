Odoo 20 Documents: centralize files without losing control

A document workspace is useful only when people can retrieve the right evidence without exposing a file that is irrelevant to them. For an Odoo business in Belgium or France, Odoo 20 Documents can organize, share and use files connected to operations. Its value relies on simple governance: ownership, access, retention and exception handling.

Start with folders that match the work

Separate company, shared and personal folders before creating a hierarchy. Teams should know where to place a signed quotation, supplier document, field report or HR file. A small number of business-readable folders is more reliable than a deep structure that nobody follows.

Odoo can automatically centralize files associated with certain apps. For Accounting, centralization cannot be disabled: subfolders are created by journal type and the journal name is added as a tag. Set this up before launching a flow, as Odoo documentation states that changed settings affect new files only.

Treat access rights as a business rule

A shared folder is not an anonymous drop box. Define who may read, edit, delete or execute an action on its documents. Also validate company boundaries: a Belgian team, a French subsidiary and a service provider should not receive the same default access merely because they share an Odoo database.

For sensitive files, assign a process owner and a review rule. Test permissions with representative accounts, rather than only with an administrator account that can see everything.

Plan deletion and automation

Items moved to the Odoo Documents trash remain there for 30 days by default; the retention delay is configurable in settings. Decide what is an operational deletion, an archive and a retention requirement for your organization. A trash folder is not an archive policy.

Custom actions and automation rules can speed up filing or approvals. They require Studio, whose installation can affect the subscription plan. AI Auto-sort also requires the Odoo AI app. Start with a pilot folder and reversible actions, then measure filing errors before scaling.

Acceptance-test a document end to end

Underside fictional scenario: a company operating in Brussels and Lyon receives a bill, a commercial contract and a field-service photo. It checks the created folder, tags, each role’s visibility, the link to the business app and recovery of a deleted file. The team confirms that an authorized user can run the intended action without being able to see HR files.

  • Map document types, their owners and their users.
  • Test read, edit, share and delete rights with real user accounts.
  • Verify the centralization of new files by app and journal.
  • Set the trash delay, archive and retention rules with the responsible stakeholders.
  • Pilot an automation or AI sorting flow on a limited scope before rollout.
  • Document exceptions: wrong folder, duplicate, denied access and accidental deletion.

Official source and scope

Odoo 20’s official Documents documentation describes folders, permissions, centralization, trash, automation and AI prerequisites. The governance and acceptance-testing recommendations are Underside’s analysis; adapt them to your security, retention obligations and Odoo deployment in Belgium or France.
